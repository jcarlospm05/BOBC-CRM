## Reproducción

Desde la raíz del repositorio, con Node para la suite de unidades:

```sh
node docs/bobc-crm/tests/node-tests.mjs --json /tmp/bobc-crm-node-qa.json
```

La suite Node usa lectura de archivos como sustituto explícito de HTTP para el cargador de esquema. Comprueba funciones reales en memoria; no usa un IndexedDB simulado ni afirma transacciones, DOM o dispositivos.

Con Python, Playwright y Chromium para la suite de navegador:

```sh
python docs/bobc-crm/tests/run_browser_tests.py --chromium /usr/bin/chromium --json /tmp/bobc-crm-browser-qa.json
```

El runner crea contextos desechables y utiliza un origen localhost. Las páginas de pruebas están deshabilitadas fuera de localhost y no ejecutan casos automáticamente. Si no puede abrir el servidor de pruebas, utiliza respuestas de archivos mediante rutas de Playwright. Si no puede iniciar Chromium, registra el error y devuelve código 1.

Casos preparados: BD nueva; migración real de 51 tablas con registros; índices conservados; pestañas bloqueadas y versionchange; 115 FK; baja/actualización protegida; instantánea consistente; v2→BD limpia→comparación por ID/contenido; legacy51 y transición96; rechazo de archivos inválidos; rollback tras fallo de escritura; exportación de recuperación; UI, JSON/CSV y persistencia.

## Límites y riesgo de datos

- Los archivos JSON de esquema, CSS e index.html mantienen exactamente sus blobs del commit fuente. No se cambió DB_NAME ni DB_VERSION; no hay migración destructiva, dominio nuevo, PWA, TypeScript o dependencia de ejecución nueva.
- Las pruebas preparadas para Pixel 7, iPhone 13 y escritorio son emulación en Chromium. No se ejecutaron; tampoco hay pruebas manuales nuevas en Android ni Safari/iOS. La prueba Android previa comunicada en el datasheet no se atribuye a esta entrega.
- Los vínculos polimórficos usan nombres de entidades del esquema. Alias históricos no documentados o pares incompletos pueden impedir restaurar/editar; la copia de recuperación se conserva para corregirlos.
- Campos ausentes no se convierten en obligatorios por su nombre. El guardado de Relaciones exige nombre, tipo y lifecycle; al restaurar se preservan omisiones históricas y se validan los campos presentes. Las reglas completas por operación/estado de cada módulo quedan pendientes.
- Valores monetarios enteros seguros no certifican pagos, saldos, presupuesto o ledger de inventario. No se implementaron invariantes financieros ni existencias.
- En respaldos se conservan fechas de texto y metadatos históricos desconocidos; la edición aplica validaciones actuales y puede rechazar fechas antiguas inválidas. Un respaldo recuperable no equivale a datos completos o semánticamente certificados.
- audit_events conserva referencias históricas aun después de eliminar el registro. Los ciclos opcionales de categorías y budgets↔projects ya existen en el esquema; no hay cascadas automáticas ni validación completa de ciclos semánticos.
- Restaurar sustituye datos base tras la confirmación existente de la UI. Se debe conservar un JSON actual; el riesgo de ejecución se sigue considerando pendiente hasta probar IndexedDB y recuperación reales.
- El producto sigue siendo un prototipo local sin autenticación, permisos efectivos ni sincronización entre dispositivos. No se declara porcentaje de cobertura global.
